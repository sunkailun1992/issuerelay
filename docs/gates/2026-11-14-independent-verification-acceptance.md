# 独立验证、退回与复验验收

## 实现范围

0.6.0 在 0.5.8 基础上新增独立验证与退回动作，使用既有的一次性预览、人工确认和运行调度。数据库升级至 schema 7。开发、验证、修复和复验保留独立记录，运行中接纳可信启动事件的原生会话 ID。

确认预览包含完整任务简报、Linear 修订、来源运行、交付标识及内容指纹、执行器、模型、推理力度和联网沙箱权限。启动、终态和标记完成复核本轮版本及条件。验证使用独立临时副本和新原生会话，允许访问任务授权的原型、服务和依赖。

## 自动化回归

- 原生进程夹具在结束前保存会话和检查点，并以实际启动时间区分重试事件。
- 同一合成任务覆盖开发、未通过的验证、确认退回、修复请求补充信息、经审核续作、修复交付、新版本复验、逐轮归档及收口。
- 旧版本、任务条件变化、缺失任务简报、一次性确认复用、重复验证、活动交接及未启动归档均被拒绝。
- 修复关联经续作、重试和数据库重载保留。
- Git 交付暂存使用固定提交的树与校验对象，覆盖未跟踪文件、隐藏索引标志、CRLF 及可执行权限。多仓清单核完整改动与内容哈希。
- Git Wiki 回执要求页面进入真实提交；有远端时要求提交存在于已获取的远端历史。登记后通过原运行读回。
- 验收结果读取失败会通过既有运行槽清理记录失败、释放目录。回归用例在验证期间破坏临时数据库的简报记录，确认不会留下没有进程的运行中状态。
- 真实运行的本机测试可显式执行 `cargo test -p issuerelay-core --test acceptance_live codex_verification_native_run -- --ignored --nocapture` 或对应 `claude_verification_native_run`。这些测试调用本机已登录的提供方，并有实际推理用量，日常测试默认跳过。可用 `ISSUERELAY_ACCEPTANCE_EVIDENCE` 指定本机私有证据目录。

## macOS 真实执行器

2026-11-14 在 Apple silicon 的隔离宿主、合成 Linear 连接和临时 Git 交付中检查真实执行器。正式应用数据和真实任务另行管理。开发源由受控夹具生成，独立验证由真实官方 CLI 执行。

Codex 0.159.2 使用 gpt-6.1-sol 和 ultra。已实测获批运行排队、可信启动事件在运行中到达、隔离副本内执行测试、原工作范围之外的写入被拒、读取宿主 localhost HTTP 夹具的实际响应，以及对应版本的结构化通过结论。服务端确认收到请求，回执随后从宿主按原运行读回；同一原生会话通过 Codex Desktop 的只读接口可定位。

Claude Code 2.1.319 已实际启动并记录合法会话，遇到账号用量限制后归类为无法完成，保留检查点和终态。该实际会话可通过官方 Desktop 接续入口打开，桌面能看到相同会话、任务与用量提示。限额后的完整模型实跑待复核。
