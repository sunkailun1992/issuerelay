# v0.6.2：工作流修正与发布前本机验证

## 本次行为

版本从 0.6.1 顺延至 0.6.2，包含已在本地收口的五项修正：

- 派发与验收预览显示有效期及明确的到期反馈，五种现有语言完整；相同 fingerprint 的新预览重新计时。提交中保留真实进度，刷新后仍需人工核对并确认。
- 独立验证在删除临时源码前保存固定目录内的报告和附件，生成大小与 SHA-256 索引；保存失败保持受阻，不能借附件缺失宣称通过。
- 显式 Codex 聊天确认配置不再被误报为未知键，不改变默认值、权限或原生确认边界。
- 返修关联被轮询读到时保持已打开的审核框及原令牌，不增加历史运行的新派发入口。
- 有完整报告的 Failed 或 Blocked 验证可经正常预览和确认退回诊断或修复；原推荐结论、状态、报告及证据保持，后续仍需新开发会话、新交付和独立复验。

发布复核另发现键盘焦点遗漏：审核入口随轮询消失后，取消对话框会丢失可聚焦目标。最小修复复用现有 `useFocusReturn`，在入口消失时回到仍有效的打开前焦点或页面标题；入口仍在时继续使用 Radix 默认恢复。没有新增文案、命令、权限或绕过确认的接口。

普通重新运行复用同一运行行和日志名，原实现会截断上一轮日志；恢复会话失败后转为新会话也经过同一路径。本次在共享引擎启动层先保存唯一的私有日志副本，再调用原执行者，当前日志提供前一轮位置供既有日志读取接口定位。暂存副本完成并同步后才以不覆盖方式发布；保全失败不启动执行者。副本与当前日志共用既有时间和总量清理预算，不增加数据库历史或绕过人工确认。

焦点区分回归先红：五种语言的实际查询缓存轮询测试均在关闭后期望标题获得焦点，实际落到 `body`；入口仍在的对照通过。最小修复后，该文件 29 项全部通过。原令牌、重读、显式确认及 busy 防重复回归保持。初次测试命令曾因额外分隔符误跑全部测试且有新增断言失败，最终结果以上述修正后的完整检查为准，没有将误跑记为通过。

Cargo 锁文件仅更新本仓四个 package 的版本，外部依赖不变。使用构建缓存的真实目录运行 Rust 检查，避免更新器的实际可执行文件边界把构建目录别名识别为另一份程序；没有为此放宽产品校验。

首轮 main CI 和手动 dry run 的 macOS 检查通过，Windows 均在 Clippy 的 `unused_mut` 处失败：私有附件目录的 `DirBuilder` 仅在 Unix 调用 `mode`，Windows 不需要该变量可变。最小修正把可变绑定限制在 Unix 分支，保留 0700、Windows 原有 ACL 继承及 `-D warnings`；没有增加 lint 例外或改变留存预算。首轮失败记录保留，正式标签仍须等待新提交的两平台 CI 与试打包通过。

第二轮 Windows 已通过 Clippy 和 541 项 core 单元测试，但附件集成测试以临时目录的原始路径字符串匹配已规范化的持久索引引用，产生路径别名的假失败；此前索引存在、附件内容及逐文件大小和 SHA-256 检查均已通过。在本机以同一文件的 `..` 别名重现该断言失败后，测试改为比较完整的规范化索引引用，保留全部文件校验；没有改动生产附件保存逻辑或放宽路径边界。相邻正常返修与再验证流程检查保持通过，正式发布仍等待新提交的两平台完整检查。

日志保全回归先在普通重试后的正常日志读取上失败，修复后覆盖三次同运行重试的唯一副本与原样字节、双派发防重复、保全失败不启动、恢复失败转新会话、真实进程启动失败的定位提示，以及年龄、总量、暂存和链接边界。综合检查曾发现首次运行无旧日志时新增异步等待导致三个宿主生命周期回归；缺失日志改为同步快路径并保持原取消机制后，36 项宿主、222 项引擎及最终全套 Rust 检查通过。既有 continuation 重试保留旧行并重新审核的回归仍通过。
