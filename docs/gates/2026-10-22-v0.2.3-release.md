## 公开后的实机核对

- 时间：2026-10-22 04:28–04:30 UTC。用的是已装的托盘程序 0.2.3（从草稿装上，就是公开的那一份），没有用开发宿主；命令行是包里的 `issuerelay 0.2.3`。开工前没有运行在进行，也没有需求在排队或等待；先备份了 `config.toml`。
- 计划建议照 10-21 的做法，用临时的 `CODEX_HOME` 造出只差精简的 Codex。这次改用 Claude：把数据目录里空的 `lean-check` 文件夹换成同名的空文件。Claude 的精简登录检查在这个文件夹里运行，建不了文件夹就记为精简问题，平常的三项检查不受影响。这样不用新登录，不改用户的执行者配置，核对的也是公开的构建。绑定一行与宿主日志由 `Readiness::held_back_by_lean` 与 `doctor::log_readiness_change` 写出，与是哪一个执行者无关。

| 项 | 做法 | 结果 |
|---|---|---|
| `bind list` 的权限档 | 沙箱绑定以 `issuerelay bind add … --executor claude --permission personal` 临时改为按个人设置 | • `bind list`：`[claude, permission personal]`；`doctor` 的绑定一行：`claude (full configuration: personal settings): ok`。<br>• 改回 `--permission auto` 以后是 `[claude, permission auto]`、`claude (lean): ok`，`config.toml` 与备份逐字节相同。 |
| 只差精简 | 换成文件以后运行 `issuerelay doctor`（每次都重新检查） | • `claude: ready`；`claude (lean runs): not ready (could not prepare the folder for the lean sign-in check: File exists (os error 17))`。<br>• 两个绑定都是 `claude (lean): executor not ready for lean runs`。<br>• 宿主日志（数据目录的 `logs/app.<日期>.log`）：`WARN … executor no longer ready for lean runs executor="claude" problems=could not prepare the folder for the lean sign-in check: File exists (os error 17)`。 |
| 修好 | 删掉那个文件、建回空文件夹，再运行 `doctor` | • 两个绑定都是 `claude (lean): ok`；宿主日志：`INFO … executor ready now executor="claude"`。<br>• 从换成文件到恢复约 36 秒，其间 `status` 一直是 `Waiting for binding: 0`。 |

- 自然出现的一次（没有人动）：03:52:22 UTC 宿主日志 `WARN … executor no longer ready executor="claude" problems=Linear MCP in claude: Failed to connect — Version negotiation probe timed out after 5000ms`，03:57:41 UTC `INFO … executor ready now executor="claude"`（见 P4）。
- 合起来，能接的运行变少（`executor no longer ready`、`executor no longer ready for lean runs`）与变多（`executor ready now`）都在实机日志里出现过。没有出现的：从什么都不能接变成只差精简（`executor ready now, but not for lean runs`）。
- 没有看：面板里绑定的那一行（文字由组件测试覆盖）。
