# 独立验收附件留存 — 本机通过

## 范围

独立执行者只向临时副本的固定 `.issuerelay-evidence` 写报告和附件。引擎结束整棵执行进程树后、清理临时源码前，将普通附件和宿主结果保存到私有 `verification-evidence/<job-id>/`，生成完整大小与 SHA-256 索引。既有运行详情与 MCP `get_run` 的验收证据列出持久索引。保存失败不得得出通过结论；不增加写入接口、配置开关、执行权限或确认入口。

## 合成回归

文件模块 17/17 通过，覆盖固定来源、空附件但有宿主报告、内容哈希、配额、路径、链接、硬链接、非普通文件、身份替换、私有权限、不覆盖和部分发布。初次实现的权限测试捕获临时目录模式错误，已在写入内容前收紧至 0700。Mac、Linux、Windows 都有明确的不覆盖发布实现；Windows 路径前缀与 Win32 调用另经独立源码复核，尚未在 Windows 实际运行。

前端构建、格式、全量 Clippy、工作区 Rust 测试、前端类型与 ESLint、前端测试及严格扫描全过。Rust 1218 通过、0 失败、3 项默认忽略；前端 1327 通过、0 失败。构建目录通过既有软链接时，更新器自身的 current_exe 检查拒绝该环境；使用相同目录的真实路径后全量通过，未更改产品代码或移除软链接。

## 边界

以上不替代真实业务、已安装桌面包、Claude 或 Windows 的验收。当前用户要求只合入本地 main，未推送、升版本、发布或换装；实际本地运行采用哪份构建须单独取证。附件不受现有日志清理影响，本次未增加自动删除策略。宿主报告有长度上限；不完整原生输出仍保留于原运行日志，不能借附件保存来替代结论及版本核验。
