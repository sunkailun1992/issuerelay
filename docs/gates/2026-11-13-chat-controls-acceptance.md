# 会话控制验收

本轮在 macOS 验证会话控制的源码与自动化路径。使用合成工单、临时状态库、模拟 MCP 客户端和隔离的本机 IPC。真实工单写入及 Windows 实机均待验。

| 路径 | 证据 |
|---|---|
| 工具发现 | 编译后的 CLI 通过 stdio 完成 MCP 握手，发现 36 个工具。 |
| 操作确认 | 测试覆盖确认、拒绝、取消、客户端缺少表单、预览变化及重复提交。 |
| Codex 原生确认协议 | 使用实际 Codex CLI 0.159.2 的 App Server、独立临时配置和合成 IPC。客户端收到原生表单请求；拒绝或取消均无提交，接受恰好提交一次，重放旧预览被拒绝。未调用模型或连接真实 Linear，未进行 GUI 人工点击。 |
| Claude Code 原生确认 | 使用实际 Claude Code 2.1.319 交互式终端、隔离配置、环回模型替身和合成 IPC。控制服务协商至 MCP 2025-11-25；实际终端展示设置变更和原生表单，拒绝无提交，确认恰好提交一次。未连接真实模型服务或 Linear。 |
| 运行和配置 | 引擎测试覆盖派发、接续、停止、重试、待验收、完成、方案收口及绑定与设置复核。 |
| 诊断 | 使用替身核对连接、更新和系统状态的输出，避免向会话返回原始诊断或凭据。 |
| 回归 | Rust 1,167 项与前端 1,307 项通过，前端构建、格式、Clippy、lint 与公开仓库扫描通过。 |

待实机：真实测试需求的状态读回，以及 Windows 安装和操作。发布工作流核验安装包，不代替真机验收。

### 长简报与团队标签补验

- 用 Codex 桌面自带的 `0.167.0-alpha.4.1` App Server、独立临时配置和新编译的 IssueRelay `test_confirmation_form` 实测协议。`never` 或关闭 `mcp_elicitations` 时，客户端直接回传 `client_declined`。可信项目启用 `mcp_elicitations` 并使用用户审核后，发出原生表单请求，测试客户端取消，IssueRelay 收到 `cancelled`。没有连接 IssueRelay 宿主、Linear 或模型。桌面 GUI 的人工点击另验。
- 通过合成 IPC 与 MCP 客户端验证中文长简报。保留同一指纹和简报修订号，表单要求用户先核对会话预览。修改长简报尾部会使旧指纹失效，表单不会打开，也不会提交。该路径没有实际派发需求。
- 对 Linear 官方 MCP 做只读对照，按项目关联团队读取标签时，能补齐工作区查询漏掉的团队标签。自动化回归覆盖工作区标签、团队标签分页、重复团队和同名标签。新构建的桌面分流选择器另验。
