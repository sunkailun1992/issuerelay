# 已知 Codex 聊天确认配置键误告警 — 本机回归通过

## 问题与修复

`settings.codex_chat_confirmation` 已是受支持的布尔配置，加载显式 `false` 与 `true` 均正常。默认 `false` 通过 `skip_serializing_if` 省略，而 `unknown_keys` 以默认配置的序列化结果构造已知键模板，因而漏列合法键，误报其将被忽略或丢弃。

修复仅将 `unknown_keys` 的函数局部样本设为可序列化的 `true`，使合法字段进入已知键模板，并把注释及保存键回归测试扩展到省略默认值的布尔字段。运行默认值仍为 `false`，实际配置的加载值、权限、一次性确认与审批流程均不改变；没有增加自动批准入口，也没有读取或改写真实用户配置。

## 回归证据

先添加两项合成测试，分别显式设置 `false` 与 `true`。修复前两者的反序列化值断言均通过，但未知键结果错误包含合法键，因此 2/2 按预期失败。修复后合法键不再告警，故意拼错的邻近键仍准确列为未知；两种值经保存、重载后保持。

`config` 单元套件 52 通过、0 失败。完整七项检查均退出 0：前端构建、Rust 格式、全工作区 Clippy、Rust 工作区测试、前端类型与 ESLint、前端测试和严格密钥扫描。Rust 合计 1220 通过、0 失败、3 项默认忽略；前端 58 个测试文件、1327 项通过、0 失败。Cargo 使用既有构建目录的 canonical 路径，未改动目录软链接。
