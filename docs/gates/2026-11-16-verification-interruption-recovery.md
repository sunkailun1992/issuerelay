# 验证中断证据恢复 — 合成回归通过，待实机

## 范围与行为

基于 `d3f223311eb691bdb81485a38d46435b16ad82e0`，将独立验证的活动工作目录从系统临时区移到应用数据目录的私有 staging。宿主在执行者可写子目录之外，以独占写入和同步落盘保存运行、尝试与获准源指纹的标记。保持既有 sandbox、网络、权限、证据预算和原生确认入口。

正常结束只在证据发布及结果事务都成功后清理 staging。重新初始化时，先走既有旧进程处理，再核对宿主标记、当前运行、尝试和源指纹，沿既有安全留存流程接回固定证据目录。恢复结果始终为 Blocked，明确标为部分且未验证；不生成执行者 final、不恢复业务动作、不采用旧 final 的通过结论。标记或来源不匹配、多尝试歧义、链接、超限、损坏或冲突均保留原件并警告。旧版本已丢失的文件无法重建。

中断结束时间与证据恢复时间分开：保留原 `finished_at`、会话与已报告用量，新部分宿主报告单列 `recovered_at`。相同 recovered/unavailable 结论再次初始化不写历史行、不重复发出更新事件，已发布 payload 仍重新校验。五种 locale 的详情提示区分已恢复、无法恢复和旧记录恢复结果未知，不把基础设施中断归为业务验收失败。

## RED 与修复验证

先用真实 Engine 和合成执行者复现两类旧缺口：验证 cwd 仍在系统临时目录，以及已写 raw、尚无 final 的宿主任务消失后原件被清理。随后通过私有运行时中断模拟与初始化测试验证修复，没有结束实际应用或重启机器。
