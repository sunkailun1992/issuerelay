# 返修派发审核框的轮询生命周期回归（2026-11-16）

## 问题与修复

独立验收退回后，详情页可以打开派发预览。后台轮询建立返修运行关联时，`repair_job_id` 从空值变成待复核运行编号。原实现会同时卸载预览按钮和它拥有的 Dialog，正在核对的审核框因此消失。

本次让退回分支持续挂载 `DispatchReviewButton`，只用可选的 `showTrigger` 控制旧页入口是否显示。已打开的审核框保留原来的预览、令牌及提交状态；关闭后仍销毁预览副本。返修运行已经存在时，历史页保留原有的返修运行链接，新的审核从该运行详情页进入。其他调用默认显示入口。

没有更改预览读取、时效、令牌、指纹、CAS、授权或后台审批条件。轮询不会自动提交或悄悄替换正在审核的令牌。后端拒绝失效预览后，界面继续显示既有的多语言错误与重新读取入口；重新核对后仍需明确确认。

## 合成回归

动态假后端从无返修关联切换到 `waiting_binding` 且原因为待派发复核的返修运行；刷新真实查询缓存后再断言界面结果。

- 英文、简体中文、繁体中文、日文和韩文分别验证同一个 Dialog 节点仍存在，预览仅读取一次，没有自动批准；取消后旧页只保留返修运行链接。
- 旧令牌被后端拒绝时，错误可见且确认禁用；重新读取会展示新的简报内容，只有再次明确确认才提交新令牌。
- 已提交但未返回时，轮询不卸载 Dialog、不解除忙碌状态；Escape、取消及重复点击不会产生第二次提交。

原代码的六个新增回归用例失败；修复后再补提交中轮询用例，相关组件和运行详情共 153 个用例全部通过。新增用例共七个，使用现有五语言文案，没有新增或修改 locale 键。
