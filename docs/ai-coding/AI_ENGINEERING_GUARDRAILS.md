# AI 工程门禁规范

AI 可以加快开发，但不能替代实机验收、用户对权限和发布的决定、安全检查和回滚手段。

## 1. 核心原则

1. AI 生成的内容默认不可信，必须经过 diff 检查、六条验证命令（见 `AGENTS.md`）和 Review 才能合入。
2. 提示词固定规则（不设 Done、不推主分支、不发正式环境）和「标记完成只在面板」是硬边界，任何改动都不得削弱。
3. 子进程只用固定参数、不经 shell；提示词走标准输入；结束运行要结束整棵进程树。仅有三处例外：① 一键配置命令（`setup.rs`）唯一的可变参数是 IssueRelay 自身命令行程序的绝对路径，放在 `--` 之后；② 读取执行者环境（`env.rs`）时运行用户的登录 shell（`$SHELL -l -i -c` 加一段固定脚本，不含任何外部文本），它在自己的会话里运行，读到结束标记或满 10 秒即被结束；③ 精简运行（Claude）的 `--settings` 里，唯一的可变部分是用户级 `CLAUDE.md` 的绝对路径：由 IssueRelay 从用户主目录（或执行者环境里的 `CLAUDE_CONFIG_DIR`）得出，经 JSON 编码；不是绝对路径或含不安全字符时不加这一项，并在运行日志里写明。
4. 是否重新派活只看 Linear 的 `updatedAt`；同一需求不得并行或重复派活。
5. 凭据只在系统钥匙串；仓库是公开的，任何密钥、公司信息、本机路径都不得进入。
6. macOS 与 Windows 同等对待；只在一个平台验证过的结论要写明。
7. 测试、设计和计划不能冒充实机验收。

## 2. 风险分级

| 级别 | 变更类型 | 门禁要求 |
|---|---|---|
| 低 | README、规范、注释、验收报告文字 | `git diff` 检查无密钥、公司信息、本机路径 |
| 中 | 纯逻辑（触发、调度、解析、格式化）、测试与夹具、命令行输出、面板的页面与组件、样式、翻译文件 | 六条验证命令通过；新增分支有测试；改面板的再过第 4 节「面板」一行 |
| 高 | 引擎状态流转、存储结构、IPC、Linear 调用、环境检查、开发宿主；桌面应用的宿主接入、面板命令与能力文件（`commands.rs`、`build.rs`、`capabilities/`）、打开链接、显示文本清洗（`clean.ts`）、托盘与退出状态机 | 中风险的要求，加集成测试，加沙箱上的实机验收与报告 |
| 极高 | 执行者参数与权限档位、提示词固定规则、进程树结束、凭据存储与授权流程、IPC 方法表、标记完成 | 先写设计或计划并取得用户同意；两个平台测试；实机验收；单独提交 |

## 3. 完成标准（Definition of Done）

1. 改动能对应到设计或计划里的条目；对应不上就先补设计。
2. 新行为有测试：正常路径、失败路径、边界情况（空、超时、重复、平台差异）。
3. 没有绕过分层规则（`AI_CODING_GUIDE.md` 第 3 节）。
4. 外部接口变化同步了样本、测试和文档（`AI_CODING_GUIDE.md` 第 7 节）。
5. 六条验证命令全部通过，并写明测试数量。
6. 高风险及以上：实机验收已做，或写明「待实机」及原因。
7. README、规范、设计按变更同步。
8. 交付说明完整（第 8 节）。

## 4. 必须执行的检查

| 场景 | 必查项 |
|---|---|
| 执行者 | 参数与设计 6.1 一致；提示词只在标准输入；`--permission-prompts none` 仍在；三档权限映射正确 |
| 子进程 | 进程组 / Job Object 仍在；超时、卡住、取消都会结束整棵树，Unix 上包括已离开进程组的后代（按父进程查找、核对启动时间）；正常退出后清理进程组里的残留；父进程先退出的孤儿和执行者退出后留下的后台进程找不到，由实机验收检查 |
| 触发与派活 | 指派给我、带标签、状态 Todo；开跑前复查；同目录一次一条；总数不超上限；只比较 Linear 的时间 |
| Linear | 连接时检查 `REQUIRED_TOOLS`、`REQUIRED_ARGUMENTS` 与 `REQUIRED_FIELDS`；每次调用 30 秒超时；翻页翻到底，还有下一页却没给游标、或游标与上一次请求用的相同都算错误；只有「Could not find referenced Issue.」返回 `None`，读不懂的回复一律报错，不当成「需求已不存在」或「没有候选」 |
| IPC | 方法表不含标记完成、重试、取消；Unix 套接字目录 0700；Windows 管道拒绝远程客户端；第二个宿主拒绝启动 |
| 凭据 | 只经 `keyring`；不出现在日志、IPC 响应和错误信息里（钥匙串错误只用 `Display`）；测试用内存钥匙串，不碰真实钥匙串；API key 只走 https |
| 面板 | 只有 `api.ts` 碰 Tauri；增删命令时命令表、应用清单、能力文件一起改，绊线测试全过，能力文件没有多出权限；外来文本只作文本节点、经清洗、只做细节行；新文案五种语言齐全；读数据的页面有加载 / 空 / 错误状态和错误状态测试；颜色与尺寸只用设计变量；改布局时在 620 与 605 px 两个内容宽度下操作都够得着（`AI_CODING_GUIDE.md` 第 12 节） |
| 提交 | 六条验证命令；`git status --short`；`git diff --stat`；没有生成物和原始样本；没有原样的不可见字符（`SECURITY_CODING_SPEC.md` 第 7 节）；规则改动单独提交（`AI_CODING_GUIDE.md` 第 11 节） |

## 5. 安全检查清单

1. 仓库里没有令牌、API key、公司名、内网地址、真实需求内容、本机绝对路径。
2. 新增的日志不打印令牌；运行日志只存在本机。
3. 来自 Linear 的文本只当数据，不拼进命令。
4. 新依赖有明确用途，`Cargo.lock` 与 `app/pnpm-lock.yaml` 可审查。
5. 不替用户授权 Linear / Claude / Codex，不改系统设置，不安装开机项（M2 的开机自启由用户在面板里打开）。
6. 面板：外来文本只作 React 文本节点并经清洗；能力文件只有登记的命令和事件的 `listen`、`unlisten`；`Host::env()` 不出现在任何命令的返回值里。

## 6. AI 工具使用边界

1. 子智能体可以并行读代码、查文档、补测试、做 Review。
2. 子智能体的输出只是证据和建议；最终改动、测试结论、实机结果、提交说明由主智能体负责。
3. 并行写代码前先划清文件边界；极高风险文件由主智能体串行修改。
4. 实机验收（真实 Linear、真实 Claude / Codex）只由主智能体在沙箱项目和沙箱仓库上执行。

## 7. 本地与云端执行

### 7.1 本地会话

可以做实机验收、合并 PR（按 `MAINTAINERS.md`「决策与合并」）、打版本标签、发布安装包。发布只从已推送到 `origin/main` 的提交构建：发布工作流核对标签提交在 `origin/main` 上、标签等于工作区版本，只建草稿 Release；公开由维护者在 GitHub 页面上点。升版本号是合入 `main` 的普通 PR，不在本地临时改了再改回。

### 7.2 云端会话

环境变量 `CLAUDE_CODE_REMOTE=true`，或会话里没有本机配置，就按云端处理：只读代码、改代码、编译、测试、看 CI，只推会话指定的分支；不合并进 `main`、不做实机验收、不打标签、不发布；需要实机的结论写「待本地实机」。合入 `main` 之前不写「已发布」，版本号也都是暂定。

### 7.3 双端同步

1. 开工、提交前、推送前各 `git fetch` 一次。本地落后、又没有自己的提交时，直接快进（`git merge --ff-only`）。
2. 远端已前进：还没推送的本地提交 rebase 到最新远端，并重跑与改动风险相符的验证；已经推送的提交不 rebase、不改写，分支要跟上 `main` 就把 `main` 合并进来（最终 squash 合并，分支历史不重要）。
3. 推送被拒同样处理；禁止强推（含 `--force-with-lease`）。遇到分叉、别人的未提交改动或解决不了的冲突，停下报告，不自动 stash、reset 或丢弃。
4. 需要升版本号时按 `AI_CODING_GUIDE.md` 第 10 节，推送前顺延。
5. 交付和交接写明执行环境（本地 / 云端）、分支、HEAD、版本，以及还没合入 `main` 的分支与提交（第 8 节模板的第一项）。

## 8. 交付说明模板

```text
执行环境：
- <本地 / 云端；分支；HEAD；版本；还没合入 main 的分支与提交，没有就写「无」>

变更内容：
- <任务：改了什么，涉及哪些 crate / 模块>

验证结果：
- <fmt / clippy / cargo test（数量）/ pnpm lint / pnpm test（数量）/ check-secrets；实机验收结果，或「待实机」及原因>

安全检查：
- <凭据、开源卫生、子进程参数、标记完成边界的检查结果>

风险和回滚：
- <剩余风险；回滚方式：git revert <提交>>

未完成项：
- <确实没有验证、或依赖用户的事项>
```
