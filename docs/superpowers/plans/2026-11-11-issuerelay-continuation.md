# 中断运行续作实施计划

设计见[中断运行续作设计](../specs/2026-11-11-issuerelay-continuation-design.md)。本次涉及执行器参数、调度、数据库迁移和桌面命令，按对应风险门禁验证。

## 存储和接续调度

- 在 `crates/core/src/workflow.rs`、`workflow_store.rs` 和 `store.rs` 增加接续意图，升级数据库到 schema 5。确认事务保存精确的上下文、证据和执行去向。复用同一需求未开始的待续作记录，或增加一次尝试，保留源运行。
- 在 `crates/core/src/engine/dispatch_review.rs` 和 `engine.rs` 校验源运行、原目录、模式及当前 Linear 需求，预览原生恢复或新会话交接。实现续作可接受显式的 In Progress，面板和宿主不因此改写 Linear。
- 复用官方 CLI 的原生恢复参数。启动前重查已确认的策略。原生恢复失败时停止，切换执行器时显式开启新会话。两者均向标准输入提供已确认的结构化续作资料，保留提示词固定规则。
- 验证持久化、重启、重复确认、尝试接管、来源变更、权限和目录变化、原生失败后停下及并行派工条件。

## 面板与会话读取

- 在运行详情和待办操作接入「继续上次」，显示接续策略、实际去向、权限、当前完整任务上下文和已记录证据。确认后进入本次尝试的运行详情。覆盖两个执行器的选择、预览失效、取消和显示边界。
- 通过 `crates/core/src/provider_sessions.rs` 与桌面命令读取 Codex App Server 的只读近期预览。验证 RPC、会话身份和输出边界，保留官方重新打开命令。Claude Code 通过官方客户端查看。原生会话预览不复制到续作提示词。
- 验证五种语言及最小窗口。核对新命令只出现在桌面授权表。用假服务确认预览没有推理请求或直接会话文件操作。

## 验收与文档

- 运行仓库的前端构建、格式、Clippy、工作区测试、lint、面板测试与密钥扫描。记录自动化结果和实机差异。
- 在独立沙箱验证真实 Linear、两个官方 CLI 的恢复与打开、目录一致性、原生清理边界以及 Windows 的对应行为。未完成的路径写明待验。
- 同步使用指南、安装与回退说明。已发布的安装包状态与当前源码验证分别记录。
