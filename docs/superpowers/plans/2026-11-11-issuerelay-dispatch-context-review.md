# 派发前上下文预览实施计划

设计见[派发前上下文预览设计](../specs/2026-11-11-issuerelay-dispatch-context-review-design.md)。本次调整引擎调度、任务上下文存储语义和桌面命令，按高风险变更验收。

## 1. 本机草稿与确认记录

- 在 `crates/core/src/engine/workflow_support.rs` 及相关工作流类型保留按需求内部 UUID 定位的修订草稿。现有 MCP 接口沿用原有参数，并支持单独提交可选的 `conversation_history`。
- 在 `crates/core/src/workflow_store.rs` 写入确认记录，与对应上下文保存共用一个事务。比较需求更新时间、确认的修订及执行去向。更新数据库为 schema 4，保留 schema 3 的迁移路径。
- 验证首次与重复确认、修订冲突、确认过期、空上下文和未确认草稿的存储边界。覆盖 96 KiB 历史和 128 KiB 序列化上下文限制及未超限内容保真。

## 2. 调度与桌面预览

- 在 `crates/core/src/engine.rs` 的候选、等待和最终启动路径校验确认。重跑重新进入待确认流程。复用既有运行快照传递已确认的上下文。
- 在 `app/src-tauri` 注册桌面预览与确认命令。通过面板已有 API 层接入「需求」页，显示执行去向、Wiki 目录及结构化上下文，处理取消、错误和重新读取。在方案运行详情接入同一需求的「执行开发」，未准备时通过安全的 Linear 链接完成用户侧设置。
- 验证无确认时假执行器不启动，确认后只启动一轮，Linear 或绑定变化使确认失效。面板测试覆盖取消、提交预览标识、失败重试、空上下文及方案转开发时的需求身份校验。验证两个执行器均从启动快照接收确认内容。

## 3. 文档与验收

- 同步 README 和使用说明，区分当前源码和已发布的安装包。
- 运行 `pnpm --dir app build`，再运行 `AGENTS.md` 所列六条验证命令。核对桌面命令权限、最小窗口、五种语言和隐私边界。
- 在合成数据或沙箱中验证真实运行边界。将未执行的实机步骤和原因记录在验收报告。提交前重新核对远端和本地差异，按仓库约定使用英文 Conventional Commit。
