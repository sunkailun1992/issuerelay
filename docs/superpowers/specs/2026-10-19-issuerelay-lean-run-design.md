- 范围：总设计第 18 节第 6 条「精简运行」。改的是执行者参数，属于极高风险（`docs/ai-coding/AI_ENGINEERING_GUARDRAILS.md` 第 2 节）：本设计经用户同意后才写计划，实现单独提交，两个平台都要测试，并在沙箱上实机验收。
- 实测环境：macOS 27.0.1、Claude Code 2.1.285、codex-cli 0.159.2，2026-10-19 在沙箱目录里实测（第 4 节）。

## 一页概览

- **做什么**：无人值守运行默认只带 Linear 的 MCP 服务和目标仓库自己的规则与设置，不带用户本机的其他 MCP 服务（包括插件提供的、claude.ai 连接器）、插件、用户级技能与钩子、自动记忆和用户级指令文件。
- **为什么**：运行处理的是不可信的需求文本，默认权限又是完全放开。实测现有参数会载入 40 个 MCP 服务、371 个工具，其中有邮件、云盘、聊天连接器和本机控制类工具；插件的会话结束钩子另起后台进程、脱离进程树；一次真实需求的运行里，AI 把这次的事写进了用户的自动记忆。运行能用的东西越多，被需求里夹带的指令利用的面就越大。
- **怎么做**：
  - Claude：`--strict-mcp-config` 加只含 Linear 的 `--mcp-config`；`--setting-sources project,local` 不读用户级设置，用户装的插件、用户级技能与钩子随之都不加载；环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 关掉自动记忆；`--settings` 的 `claudeMdExcludes` 排除用户级 `CLAUDE.md`，为此在「参数里不放路径」的硬规则加第三处例外（L5）。
  - Codex：`--ignore-user-config` 不读 `~/.codex/config.toml`；`--disable` 关掉钩子、插件、ChatGPT 连接器与记忆；用 `-c` 只定义 Linear 一个服务并设为必需，技能目录不给模型看。用户级 `~/.codex/AGENTS.md` 在当前版本去不掉，项目的 `.codex/` 层也不生效，这两处写明后照做（L6）。
  - 两边都沿用用户已有的登录与 Linear 授权。授权是按服务名保存的，所以服务名必须与一键添加用的相同：Claude `linear-server`，Codex `linear`。
- **默认**：开。每个绑定可以单独关；已有绑定的配置里没有这一项，按开处理。「按个人设置」档位不做精简。
- **推理力度**：新增可选的推理力度设置（设置页一个全局默认，绑定可以另选；不填就用执行者自己的），精简与否都按它传，补上不读用户设置后丢掉的推理力度（L7）。
- **代价**：用户级设置（Claude 的 `~/.claude/settings.json`、Codex 的 `~/.codex/config.toml`）在精简运行里都不生效，例如推理力度、权限规则、写在里面的登录方式与模型服务（第 5.4 节）。会换掉登录或模型服务的情况，环境检查会拦下，不悄悄切过去（第 7 节）。

## 1. 背景与目的

- M0 发现：无人值守运行会加载用户本机 Claude Code / Codex 的全部配置：用户级指令文件、插件、钩子和全部 MCP 服务器。总设计第 14 节与 README 的安全须知写明了这一点，是否提供只加载 Linear MCP 的运行方式留作第 18 节第 6 条。
- M2 评估（`docs/gates/2026-10-14-m2-acceptance.md`「精简运行评估」）：Claude 加 `--strict-mcp-config` 只加载 Linear 可行，沿用已有授权，启动约快 40%；Codex 的 `-c mcp_servers=…` 是合并进用户配置而不是替换。DEMO-24 的 Codex 运行调用了用户全局配置里的个人知识库 MCP。
- M3 验收 N3（`docs/gates/2026-10-14-m3-acceptance.md`）：运行被取消时，用户自装插件的会话结束钩子另起了一个后台进程，它建了新进程组、父进程退出后归 launchd，不在 IssueRelay 能结束的进程树里。
- 一次真实需求的运行里，AI 自述「更新了两条自动记忆」：处理不可信的需求文本时，把内容写进了用户的长期记忆，用户之后自己的会话会读到它。

目的：让每次运行只带完成这条需求要用的东西：Linear 的工具、目标仓库的规则与设置、执行者自己的内置能力。

## 2. 目标、非目标与反目标

**目标**

1. 精简运行只连 Linear 一个 MCP 服务，沿用用户已有的 Linear 授权；Claude 与 Codex 都做。
2. 不加载用户装的插件、用户级技能、用户级钩子；不读也不写自动记忆；不读用户级指令文件（Claude 靠 L5 的路径例外做到；Codex 当前版本做不到，L6）。
3. 目标仓库自己的指令文件（`CLAUDE.md` / `AGENTS.md` 及其导入）与项目设置（`.claude/settings.json`、`.claude/settings.local.json`，包括项目钩子、项目启用的插件）照常生效。Codex 只保留项目的 `AGENTS.md`，项目的 `.codex/` 层做不到（第 5.2 节，L6）。
7. 推理力度可以在 IssueRelay 里设，精简与否都生效（第 5.6 节，L7）。
4. 三档权限的含义不变。「按个人设置」本来就是沿用用户的全部设置，它不做精简。
5. 默认开，按绑定可关；环境检查能说清精简运行缺什么，并给出修复办法（第 7 节）。
6. 精简没有生效时不静默退回完整配置（第 8 节）。

**非目标**

- 按绑定另选额外的 MCP 服务（白名单）。目标仓库 `.mcp.json` 里的服务在精简运行里同样不加载；要用它们或别的 MCP 服务的绑定，关掉精简运行（L1）。
- 收紧执行者的内置工具（联网、定时任务、推送通知、远程触发等）。可以作后续。
- 隔离凭据。AI 仍以用户身份运行，能用用户的 git、SSH 和各种命令行凭据。精简运行缩小的是 MCP、插件、钩子、记忆这一面，它不是沙箱。
- 加快「环境检查」。`mcp list` 仍会检查用户的全部 MCP 服务（M2 验收 N2）。
- 这一轮做 Windows 实机验收（暂无机器）。

**反目标**（做成这样就算失败，即使技术上能跑）

- 用户的执行者登录或 Linear 授权因此失效，要重新登录或重新授权。
- 精简运行悄悄换了登录身份或模型服务，例如平时走公司的网关或云服务，精简时却改用个人订阅，代码被发到另一处、记在另一个账上。
- 目标仓库自己的规则、设置或钩子被一起去掉。
- 精简没有生效却照常运行，用户以为已经隔开了。
- 为此在参数里放入来自 Linear 的文本，或没有经过校验的路径。

## 4. 实测（2026-10-19）

### 4.1 做法

- 在 `~/issuerelay-sandbox` 下建了一个探针仓库，放了几处标记：项目 `CLAUDE.md`、`AGENTS.md`、项目钩子（`SessionStart` 时往文件里追加一行）、项目 `.mcp.json`（一个启动不了的 stdio 服务）。
- 按托盘程序给执行者的环境运行：清空环境变量，只给 `HOME`、登录 shell 的 PATH 与代理变量，不带当前 Claude 会话自己的变量。
- 提示词要求不调用工具，只报出几处标记、自动记忆目录和可用的技能数。判读不靠 AI 的回答：
  - Claude 看 stream-json 的 `system/init` 事件（`mcp_servers`、`tools`、`plugins`、`skills`、`agents`、`memory_paths`），`--include-hook-events` 输出的钩子事件，以及会话存档里实际注入的指令（`instructions` 附件）。
  - Codex 看会话存档（rollout 文件）里的 `turn_context` 与注入的指令，再让它真调一次 Linear 的只读工具 `list_teams`。
- 权限档位单独测：让它跑一条 `echo` 并调一次 `list_teams`。

### 4.2 Claude Code 2.1.285

每一行都在上一行的基础上加参数；第一行是现有参数（设计 6.1）。

| 追加的参数 | MCP 服务 | 工具 | 插件 | 技能 | 钩子事件 | 自动记忆 | 用户级 `CLAUDE.md` | 一次简单回答 |
|---|---|---|---|---|---|---|---|---|
| （无） | 40：插件的、claude.ai 连接器、用户配置的 | 371 | 58 | 297 | 50（会话开始 13 个钩子，另有提交提示、结束时的） | 开 | 读 | 139 秒 |
| `--strict-mcp-config --mcp-config <只有 linear-server>` | 1：`linear-server` 已连接 | 94 | 58 | 297 | 50 | 开 | 读 | 97 秒 |
| `--setting-sources project,local` | 1 | 93 | 2（都是内置） | 18（都是内置） | 只有项目钩子 | 开 | 读 | 4 秒 |
| `--settings '{"autoMemoryEnabled":false}'` | 1 | 93 | 2 | 18 | 只有项目钩子 | 关 | 读 | 4 秒 |
| `--settings` 里再加 `claudeMdExcludes`（用户级 `CLAUDE.md` 的绝对路径） | 1 | 93 | 2 | 18 | 只有项目钩子 | 关 | 不读 | 4 秒 |

另外几条：

- 项目 `CLAUDE.md` 与项目钩子在每一行都生效；项目 `CLAUDE.md` 里用 `@AGENTS.md` 导入的规则，在第 5.1 节的整组参数下照常读到。项目 `.mcp.json` 里的服务在加了 `--strict-mcp-config` 之后不再加载。
- 子代理：不读用户级设置后只剩 5 个内置的（原来 42 个，大多来自插件）。
- 自动记忆也可以用环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 关掉，效果相同。
- `claudeMdExcludes` 只认绝对路径：写成 `~/.claude/CLAUDE.md` 不生效。
- 官方文档（Agent SDK 的说明表）说不读用户层设置时 `~/.claude/CLAUDE.md` 也不读；实测 2.1.285 与本机桌面版自带的 2.1.299 都仍然读，以实测为准。2.1.299 的其余结果与上表相同。
- 授权按服务名保存：同一个网址，在 `--mcp-config` 里换一个服务名，状态就是 `needs-auth`。
- 用时差别主要来自推理力度：本机用户级设置里把推理力度设成了最高档，不读用户级设置后回到默认档。
- 三档权限在精简参数下：「完全放开」「自动审查」都能跑 Bash 并调用 Linear 工具；「按个人设置」（`dontAsk`）照旧拒绝没有预先允许的 Linear 工具（与 M0 一致），而且不读用户级设置后，用户设置里预先允许的规则也不算了。
- `claude mcp list` 不认 `--strict-mcp-config`，环境检查没法用精简参数去跑 `mcp list`；`claude --setting-sources project,local auth status` 可以运行，本机是 claude.ai 订阅登录，结果仍是已登录。
- 本机用户级设置里有两个钩子（执行 Bash 之前一个、会话结束一个），加了 `--setting-sources project,local` 之后都不再运行。

### 4.3 codex-cli 0.159.2

基础参数是 `exec --json --dangerously-bypass-approvals-and-sandbox`（「完全放开」）。

| 追加的参数 | 插件 | 模型看到的技能目录 | 用户级 `~/.codex/AGENTS.md` | 项目 `AGENTS.md` | 推理力度 | Linear `list_teams` |
|---|---|---|---|---|---|---|
| （无） | 11 个，含电脑操作与浏览器 | 31 个，含用户级 | 读 | 读 | 用户配置的档位 | （没测） |
| `--ignore-user-config --disable hooks --disable plugins --disable memories -c mcp_servers.linear.url=https://mcp.linear.app/mcp` | 无 | 14 个，用户级仍在 | 仍然读 | 读 | 默认 | 成功，沿用已有授权 |
| 同上，但 `-c` 里的服务名换成别的 | — | — | — | — | — | 要求授权（`AuthRequired`） |
| 第 5.2 节的整组参数 | 无 | 0（目录不给模型看） | 仍然读 | 读 | 默认 | 成功 |
| 整组参数，但服务名换成别的（`required=true`） | — | — | — | — | — | 7 秒内退出（退出码 1）：必需的 MCP 服务初始化失败，没有调用模型 |

另外几条（实测）：

- `-c` 的值不加引号也行：解析不成 TOML 时按原样当作字符串。
- 加了 `--ignore-user-config` 后，本机用的模型没变，推理力度从用户配置的档位回到默认。
- 探针仓库里放的项目级 `.codex/config.toml`（定义了一个 MCP 服务）在两种参数下都没有加载：这个仓库不在用户配置的信任列表里。
- 开发中的开关 `skip_host_skill_discovery` 打开后，用户级技能照样列出。
- `codex -c cli_auth_credentials_store=file login status` 与精简运行读登录的方式相同，本机结果是已登录。
- 「自动审查」（`--approve-for-me`）加第 5.2 节的整组参数：Bash 与 Linear 工具都能用。

查官方文档与 0.159.2 的源码得到的（没有逐条实测；源码路径相对 `openai/codex` 的 `rust-v0.159.2` 标签）：

- `--ignore-user-config` 把用户配置层换成空表，系统与管理员下发的配置、`-c`、`--enable`、`--disable` 照常生效（`codex-rs/config/src/loader/mod.rs`）。项目是否受信任记在被忽略的用户配置里，所以项目的 `.codex/` 层（项目配置、项目钩子、项目规则）一起不生效；项目的 `AGENTS.md` 照读。
- 仍然会读的：`~/.codex/AGENTS.md`（没有任何参数或配置项能跳过它，唯一的办法是换一个 `CODEX_HOME`，那样登录也跟着换掉）；用户级技能目录仍会被扫描，只能用 `skills.include_instructions=false` 不把目录给模型看；用户的执行策略规则 `~/.codex/rules/`（加 `--ignore-rules` 才不读）；用户的 `~/.codex/hooks.json` 会被找到，但没有信任记录，不会运行。
- ChatGPT 账号里装的插件不靠配置文件，要 `--disable plugins` 才去掉；内置的 `codex_apps` 服务（ChatGPT 连接器）在 `apps` 功能开着、用 ChatGPT 登录时加载，要 `--disable apps`。
- MCP 授权的键是服务名加网址的哈希（`codex-rs/rmcp-client/src/oauth.rs`），所以名字与网址都要与 `codex mcp login` 时相同。
- 没有 `required=true` 时，第一轮只等可选服务 1 秒（`mcp_optional_startup_grace_ms`），Linear 的工具可能赶不上第一次请求；源码里的启动超时是 30 秒，与文档写的 10 秒不同，所以显式给出。
- `codex exec` 的事件流里没有列出已加载 MCP 服务的事件；每次 MCP 调用的 `item.completed`（`mcp_tool_call`）带着 `server` 字段。
- 记忆：只从交互式会话里提取，`codex exec` 的运行本来就不会被写进记忆；`--disable memories` 让这次运行也不读。

### 4.4 结论

- Claude：第 5.1 节那组参数做得到 L2 的全部要求，登录与 Linear 授权都不受影响。
- Codex：MCP、插件、ChatGPT 连接器、钩子、记忆做得到，Linear 授权能沿用，所以按 L4 一起做。与 L2 有两处出入：用户级 `~/.codex/AGENTS.md` 去不掉；项目的 `.codex/` 层（项目配置、钩子、规则）也一起不生效（第 5.2 节）。用户接受这两处（L6）。
- 这些结论只对上面的版本成立。执行者经常自动升级，参数的含义可能变，所以第 8 节在每次运行开始时核对一次。

## 5. 参数

### 5.1 Claude

精简时，在设计 6.1 的现有参数后面追加下面这些。它们都是固定字符串，JSON 由程序里的常量拼出，不含任何来自 Linear 或用户输入的文本：

```text
--strict-mcp-config
--mcp-config {"mcpServers":{"linear-server":{"type":"http","url":"https://mcp.linear.app/mcp"}}}
--setting-sources project,local
--settings {"claudeMdExcludes":["<用户级 CLAUDE.md 的绝对路径>"]}
```

另给执行者的环境加一个变量：`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`。

- `--strict-mcp-config` 与 `--mcp-config`：只用这一份 MCP 配置，忽略用户、项目、本地作用域的配置以及 claude.ai 连接器和插件带的服务。服务名与网址用一键添加命令的那两个常量（`setup.rs` 的 `linear-server` 与 `LINEAR_MCP_URL`），这样才能沿用用户已经完成的授权。
- `--setting-sources project,local`：不读 `~/.claude/settings.json`。用户装的插件（由用户设置的 `enabledPlugins` 启用）、用户级技能、用户级钩子都随之不加载。项目设置与 `settings.local.json` 照读，项目启用的插件与项目钩子照常生效。管理员下发的设置（managed settings）不受这个参数影响，照常生效。
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`：这次运行既不读也不写自动记忆（官方文档写明，Agent SDK 的隔离建议也用它）。用环境变量而不用 `--settings` 里的 `autoMemoryEnabled: false`（两者实测效果相同），参数里就少一段 JSON（主智能体定）。关掉自动记忆不会挡住普通的文件工具：AI 仍能直接读写那个目录，这一面靠第 2 节「不是沙箱」的说明。
- `--settings` 的 `claudeMdExcludes`：排除用户级 `CLAUDE.md`。它只认绝对路径，这是固定参数规则的第三处例外（L5，第 9 节）：
  - 路径由 IssueRelay 自己得出：执行者环境里设了 `CLAUDE_CONFIG_DIR` 时是 `<CLAUDE_CONFIG_DIR>/CLAUDE.md`，否则是 `<用户主目录>/.claude/CLAUDE.md`；不看这个文件存不存在，也不读它。
  - JSON 由 serde 编码，不手拼。
  - 路径不是绝对路径、含控制字符，或含 Windows 批处理参数没法安全转义的字符时，这次不加 `--settings`，在运行日志里写一行说明，其余精简参数照加（这一项失败时仍读用户自己的指令文件，属于用户可信的内容，所以不拦下整次运行）。哪些字符算不安全，实现时按 Rust 给批处理文件转义参数的规则核对，并写进测试。
- 目标仓库只有 `AGENTS.md`、没有 `CLAUDE.md` 时，Claude 由内置插件读 `AGENTS.md`（官方文档）；精简运行不影响这一点。
- 内置的插件、技能与子代理照常可用，所以不加 `--disable-slash-commands`（主智能体定）：用户级技能已经不加载，再加它只会连内置技能和项目自己的技能一起去掉。
- 会话照常保存，用户仍能用 `claude --resume <会话 id>` 接着这次运行聊。在终端里接着聊时，用的是用户自己的完整配置。

### 5.2 Codex

精简时，在设计 6.1 的现有参数里、末尾的 `-` 之前追加：

```text
--ignore-user-config
--disable hooks
--disable plugins
--disable apps
--disable memories
--disable skill_mcp_dependency_install
-c mcp_servers.linear.url=https://mcp.linear.app/mcp
-c mcp_servers.linear.required=true
-c mcp_servers.linear.startup_timeout_sec=30
-c skills.include_instructions=false
```

- `--ignore-user-config`：不读 `~/.codex/config.toml`，用户配置的 MCP 服务、插件、钩子、通知程序（`notify`）都不生效；登录仍用 `CODEX_HOME` 里的。
- `--disable hooks|plugins|apps|memories`：分别去掉钩子、ChatGPT 账号里装的插件（连同它们的技能、MCP 服务、钩子）、内置的 ChatGPT 连接器服务、记忆。不依赖 `--ignore-user-config` 的覆盖范围。
- `--disable skill_mcp_dependency_install`：这项功能能往用户配置里写 MCP 服务；源码显示它对 `codex exec` 本来就不生效，加上只是保险（主智能体定）。
- `-c mcp_servers.linear.*`：只定义一个服务，名字用一键添加命令的 `linear`，网址用 `LINEAR_MCP_URL`，这样才能沿用 `codex mcp login linear` 存下的授权。`required=true`：服务起不来（比如没授权）时 Codex 直接退出，不会在没有 Linear 工具的情况下开始干活。值都不加引号，Windows 上经 `.cmd` 启动时少一层引号问题。
- `-c skills.include_instructions=false`：不把技能目录给模型看（主智能体定）。用户级技能在 0.159.2 只能这样处理：目录仍被扫描，但模型看不到它们的名字与说明。代价是项目自己的技能和 Codex 自带的技能也一起不列出；Codex 的项目技能很少见，需要的绑定关掉精简。
- 不加 `--ignore-rules`（主智能体定）：执行策略规则是限制，不是能力，保留用户与系统的规则更安全。
- 两处与 L2 不同、做不到的（用户接受，L6）：
  - 用户级 `~/.codex/AGENTS.md` 照读。
  - 项目的 `.codex/` 层（项目配置、项目钩子、项目规则）不生效：项目是否受信任记在被忽略的用户配置里。要恢复，只能在参数里放绑定目录的路径把它标成受信任，这又碰到「参数里不放路径」；需要它们的绑定关掉精简。

### 5.3 与权限档位

| 档位 | 精简开着时 |
|---|---|
| 完全放开 | 加上第 5.1、5.2 节的参数 |
| 自动审查 | 同上 |
| 按个人设置 | 不加（主智能体定）。这一档的意思就是「沿用你自己的设置」：Claude 的 `dontAsk` 只放行用户设置里预先允许的操作，Codex 完全按 `config.toml` 走；不读用户设置，这一档就失去意义。面板上这一档的绑定把精简运行显示为「不适用」并说明原因；绑定里存的开关值不变，换回别的档位时照旧生效 |

另外，绑定目录正好是用户主目录时，Claude 的「项目设置」`.claude/settings.json` 就是用户设置本身，精简分不开两者，也按「不适用」处理（主智能体定）。

### 5.4 不读用户级设置的后果

- Claude 用户级设置里的这些都不生效：推理力度与 `env` 里的其他变量、`language`、输出风格、权限规则、`apiKeyHelper`。
  - 推理力度由 IssueRelay 的新设置补上（第 5.6 节，L7）。
  - 登录：claude.ai 订阅登录（存在钥匙串里）不受影响，已实测。写在用户级设置里的登录方式（`apiKeyHelper`，或 `env` 里的 API key、网关地址、第三方云的开关）在精简运行里不生效。所以环境检查对精简的 Claude 绑定用同样的 `--setting-sources` 再查一次登录（第 7 节）。宿主自己环境里的 `ANTHROPIC_API_KEY` 等变量照常传给执行者，不受影响。
  - 代理：IssueRelay 本来就自己传 `HTTPS_PROXY` 等变量（设计第 8 节），不受影响。
- 用户设置里的权限规则（包括拒绝规则）也不生效。官方文档说「完全放开」下拒绝规则仍然有效，所以靠用户级拒绝规则挡危险命令的人，要把规则放进项目的 `.claude/settings.json`，或者关掉这个绑定的精简运行。README 写明。
- 管理员下发了 MCP 配置（`managed-mcp.json`）的机器上，官方文档说 `--strict-mcp-config` 会让 Claude 在启动时退出。本机没有这种配置，没测；遇到时运行会立即失败，运行记录里有执行者的原文，用户可以关掉精简。
- Codex 的 `config.toml` 里的这些都不生效：模型与模型服务（`model_provider`、自定义的服务地址）、推理力度、服务档位、`approval_policy` 与 `sandbox_mode`（「完全放开」「自动审查」本来就用命令行参数给出）、项目信任列表、通知程序、`project_doc_fallback_filenames`、按技能的开关。
  - 模型留空的绑定改用 Codex 的默认模型（本机实测与原来相同，但不保证一直相同），想固定就在绑定里填模型。用自定义模型服务的人，精简运行会改连默认的服务，要关掉精简。
  - 登录凭据的存法退回默认的文件（`auth.json`）。把 `cli_auth_credentials_store` 设成钥匙串的人，精简运行读不到登录，所以环境检查用同样的方式查一次（第 7 节）。
  - 打开了 `features.secret_auth_storage` 的人，Linear 授权可能存在另一处，精简运行找不到时会因 `required=true` 直接退出，原因写在运行记录里。
  - 给 AI 跑的命令设的环境变量策略（`shell_environment_policy`）回到默认。在那里去掉了某些环境变量（例如密钥）的人，精简运行里 AI 的命令反而看得到它们，要关掉精简。README 写明。

### 5.5 Windows

- Claude 的参数里有 JSON。执行者是 npm 装的 `.cmd` 时，Rust 会按批处理文件的规则给参数转义（引号加倍），要实机确认 JSON 原样到了执行者那里。官方安装器装的是 `claude.exe`，不经批处理。
- 用户级 `CLAUDE.md` 的路径在 Windows 上带盘符与反斜杠，经 JSON 编码后放进参数。
- `claudeMdExcludes` 按官方文档是匹配绝对路径的 glob（未实测）：路径里的 `* ? [ ] { }`，以及 Windows 上的反斜杠，都可能让排除悄悄失效，运行日志也没有说明。实机用会话存档确认排除生效；确认失效再定：让 `passable` 也挡这些字符，或在 Windows 上改传正斜线（实现评审，2026-10-20）。
- 主目录的来源：IssueRelay 用 `dirs::home_dir()`，它在 Windows 上取系统的用户目录（`FOLDERID_Profile`）；Claude Code 是 Node 程序，`os.homedir()` 先看 `USERPROFILE`。宿主以不同的 `USERPROFILE` 启动时，排除的路径与「绑定目录是主目录」的判断都会偏到另一个目录（实现评审，2026-10-20）。
- 以上待 Windows 实机。实机发现 JSON 参数到不了时，退路是把这两段 JSON 写进 IssueRelay 数据目录里的固定文件、参数里放文件路径，这又是一处路径例外，届时再请用户定。

### 5.6 推理力度（L7）

- 档位：`low`、`medium`、`high`、`xhigh`、`max`，与 Claude `--effort` 的取值相同。Codex 的 `model_reasoning_effort` 实测接受 `high` 与 `max`，`turn_context` 照实记下；其余三档实现时在沙箱核对。某个模型不支持某档时，由执行者自己报错，运行按现有规则记为失败。
- 生效值：绑定的推理力度，没有就用设置里的默认，再没有就不传，执行者用它自己的设置（不精简时就是用户的设置，精简时是执行者的默认）。
- 参数：Claude `--effort <档位>`；Codex `-c model_reasoning_effort=<档位>`，放在末尾的 `-` 之前。档位是固定的枚举值，不是自由文本，所以不算可变参数。
- 与模型名一样，三档权限都传，精简与否都传：不精简时它会盖过用户设置里的推理力度，这正是用户在 IssueRelay 里设它的意思。
- 默认不设：升级后不精简的运行行为不变；精简运行在用户设之前用执行者的默认档。
- 实测：`--effort high` 的会话存档记为 `"effort":"high"`（`system/init` 里没有这一项）；Codex 的 `turn_context.effort` 与所传一致。实机验收按这两处核对。

## 6. 配置、命令行与面板

### 6.1 配置

- 每个绑定加一项 `lean`，布尔值，缺省为 `true`；只在关掉时写进 `config.toml`（`lean = false`）（主智能体定）。旧配置文件没有这一项，按开处理（L3）。
- 不加全局默认开关（主智能体定）：用户只要求按绑定可关；新绑定默认开。以后有人要「所有绑定都关」再加。
- 生效值：`lean` 为真，并且这个绑定的生效档位不是「按个人设置」。
- 老版本 IssueRelay 读到 `lean = false` 会按现有规则提醒「不认识的配置键」，下次保存时丢掉它（设计第 11 节）。

- `issuerelay bind list`、`issuerelay doctor` 的绑定一行写明精简运行的生效值（开、关、按个人设置或主目录时「不适用」）与推理力度；`--json` 输出加对应字段。

## 7. 环境检查与就绪

- 精简的 Claude 绑定：`claude mcp list` 里要有一行，服务名正好是 `linear-server`，网址正好是 `https://mcp.linear.app/mcp`，状态是 Connected。别的名字的 Linear 服务、claude.ai 的 Linear 连接器都不算，因为精简运行不会加载它们。
- 精简的 Codex 绑定：`codex mcp list` 里要有一行，服务名正好是 `linear`，网址正好，`enabled`，并且不是 `Not logged in`。
- 登录（第 5.4 节，主智能体定）：
  - Claude：另跑一次 `claude --setting-sources project,local auth status`。它在 IssueRelay 数据目录下的一个空目录里运行：在主目录里跑时，「项目设置」就是 `~/.claude/settings.json` 本身，查不出区别。精简可用的条件是这次也已登录，并且 `authMethod`、`apiProvider` 与平常那次 `auth status` 相同；不同就说明精简运行会换一种登录或换一个服务，按反目标拦下。
  - Codex：另跑一次 `codex -c cli_auth_credentials_store=file login status`，要已登录，并且登录方式（ChatGPT 或 API key）与平常那次相同。另外读用户的 `config.toml`（只读）：设了非默认的 `model_provider`（或默认档案里设了）就算不可用，因为精简运行会改连默认的服务。
  - 两边的回答都要说出登录方式（Claude 的 `authMethod` 与 `apiProvider`，Codex 的 `Logged in using` 后面那段）：说不出就无法比较，精简判为不可用，问题写明检查做不了。执行者升级改了输出时，不能因此放过一次换了登录的精简运行（实现评审，2026-10-20）。
  - 这两条新命令每次环境检查都跑，不先看有没有精简绑定：每个执行者多一条一秒内的命令，换来检查结果不依赖配置，也不用在缓存里处理「开关刚改」的情形（计划细化第 2 条）。它们与其他检查同时进行、同样限时；没跑成只记为精简问题，不影响平常的就绪判断和它的缓存。
  - Claude 那条检查用的空目录是 IssueRelay 数据目录下的 `lean-check/`，每次检查前没有就建；建不起来时记为精简问题。
- 不满足时，绑定显示「执行者未就绪」，原因写明精简运行要用哪个名字的 Linear 服务（连同添加它的命令），或者登录、模型服务在精简运行里会变。登录与服务问题的提示建议关掉这个绑定的精简运行。
- 面板的精简一节不加一键修复按钮（主智能体定，2026-10-20）：检查报告分不清「缺这个服务」和「这个名字指向别的网址」（后者添加会失败，见下一条），要分清得给报告加字段。精简问题里写着要运行的命令；平常的一键添加与浏览器授权照旧，它们本来就用 `linear-server` 与 `linear` 这两个名字，修好平常的 Linear 服务通常也就修好了精简的。
- 这个名字已经被别的网址占用（例如旧的 `/sse` 地址）时，一键添加会失败：不替用户改他的配置，只说明原因，请用户自己处理或关掉精简（主智能体定）。
- 完整配置的绑定（精简关掉或「按个人设置」）照现有规则检查，不变。
- Linear 服务的判定从环境检查已经在跑的 `mcp list` 里读。
- 升级时不改写已有绑定（主智能体定）：Linear 服务用了别的名字的人，升级后精简绑定会停在「执行者未就绪」，概览与托盘照现有方式提示环境问题，一键添加加一次浏览器授权就好；发布说明写明。本机两个执行者都已经是这两个名字。
- 实现：执行者的检查结果里多两个结论（精简要用的 Linear 服务是否可用、精简时是否已登录），判定派活条件与绑定检查时按绑定的生效值取用。具体怎样传由实现者定。

## 8. 运行时核对

（主智能体定）

**Claude**：精简的 Claude 运行，读到第一条 `system/init` 事件时核对两件事：

1. `mcp_servers` 是数组，并且只有一项，名字是 `linear-server`（状态不管：没连上的，AI 会照常报失败）。这个字段是官方文档列出的。
2. 如果有 `memory_paths`，它的值都为空。这个字段文档没有列出（本机两个版本都有），所以没有它算正常，有了而且不空才算违反。

不符合，或者事件里缺 `mcp_servers`，就当作「精简运行没有生效」：像用户点「停止」那样结束整棵进程树，运行记为失败，原因写成英文说明 `lean run did not take effect: <细节>`（例如多出来的服务名，或 `auto memory is on`），面板按失败状态显示翻译过的标题、原因作细节行（计划细化第 1 条）；违规的那一行照常写进运行日志。

- 为什么：执行者常自动升级，参数含义可能变；精简运行是一项安全承诺，按引擎「读不懂就报错」的同一取向处理，失败即关闭。
- 读到 `init` 之前只允许出现 `system` 类的事件：实测项目的会话开始钩子的事件排在 `init` 前面。在它之前出现 AI 的消息、工具调用或结果，就当作「精简运行没有生效」，这样执行者以后改了事件名也不会让运行不经核对就跑完。进程结束时还没读到 `init` 的运行，按现有规则判定。
- 项目钩子在 `init` 之前就已经跑过：核对拦得住的是之后的工作，不是会话开始时的钩子。项目钩子本来就允许（L2）。
- 不核对插件：项目设置启用的插件是允许的（L2），`init` 事件里看不出插件来自哪一层。
- 拦下的运行各自记为失败，引擎不会因此暂停这个执行者的其他精简运行（主智能体定）。这种情况只在执行者升级改了参数含义时出现，到时每条受影响的需求要「重新运行」；要不要加一个自动暂停的开关，等真遇到再定。

**Codex**：事件流里没有列出已加载服务的事件，所以分两处：

- 开始时靠 `required=true`：Linear 服务起不来，Codex 自己就退出，运行按现有规则记为失败，运行记录里留着 Codex 的错误原文。
- 运行中：每个 `mcp_tool_call` 的 `item` 都带 `server` 字段，出现不是 `linear` 的服务就当作「精简运行没有生效」，处理与 Claude 相同。这只能在 AI 真去调用别的服务时发现，比 Claude 的核对晚，所以实机验收要看一遍会话存档。

## 9. 安全与规则

- 精简参数都是固定字符串，另加一个固定的环境变量；推理力度是固定的枚举值。唯一的可变部分是 L5 的路径，规则文字写成：「③ 精简运行（Claude）的 `--settings` 里，唯一的可变部分是用户级 `CLAUDE.md` 的绝对路径：由 IssueRelay 从用户主目录（或执行者环境里的 `CLAUDE_CONFIG_DIR`）得出，经 JSON 编码；不是绝对路径或含不安全字符时不加这一项，并在运行日志里写明。」
- 精简不改变提示词与它的固定规则。
- 精简不改变的风险：官方文档写明，`-p` 运行即使在没信任过的目录里也会跑项目 `.claude/settings.json` 的钩子与其中的 `env`、`apiKeyHelper`。绑定目录由用户自己选，这一点与现在相同，README 的安全须知照旧提醒。
- 不设 `CLAUDE_CONFIG_DIR`、不换 `CODEX_HOME`：两者都会让执行者换一份登录（钥匙串条目也跟着换）。
- `CODEOWNERS`：`crates/core/src/executor/` 与 `setup.rs` 已在列；如果把两个 Linear 服务名常量挪到新文件，新文件也登记进去。
- 「标记完成」只在面板、IPC 方法表不变，这两条不受影响。
