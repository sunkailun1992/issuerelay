# 中断运行续作设计

## 目标与取舍

运行中断后，用户从运行详情选择由 Codex 或 Claude Code 接手。预览展示实际去向、权限、接续方式和会交给执行器的内容。确认后沿用原项目工作目录，记录下一次尝试，并保留原运行供检查。手动领取交接仍适合需要在外部客户端自行接手的场景。通过官方 CLI 恢复同一执行器的原生会话，可以延续原来的对话状态。跨执行器用已核对的交接内容启动新会话，避免把执行器私有会话存储作为集成接口。

## 接续与调度

- 源运行必须实际开始且已因失败或取消而结束。只使用当前需求的最近一次中断运行，或接管为该源运行准备、仍未开始的尝试。仍在运行、已经换了工作目录或被手动领取的运行，需要先解决相应冲突。
- 用当前 Linear 工作区的需求 UUID 关联源运行。保留原执行模式、指派对象、标签和绑定校验。用户显式确认的实现续作允许 Todo 或 In Progress。方案续作仍要求 Todo。自动发现新需求仍遵循原触发条件，IssueRelay 不在续作中写 Linear。
- 用户选定执行器后，预览显示同一项目目录、模型、推理力度、权限和实际接续策略。若设置允许，原生会话 ID 有效，同一执行器在原目录且满足期限及模式限制，使用官方 CLI 恢复。切换执行器或不符合原生恢复条件时，显示交接并开启新会话。启动时复核已确认策略。恢复失败保留可见错误，不自动另开会话。
- 确认令牌绑定源运行、需求 UUID 与更新时间、目标目录及执行设置、任务上下文修订和已记录证据。确认前重读，变化则重新预览。schema 5 持久保存确认的接续信息及相应尝试。新记录或尚未开始的既有尝试承载续作，源运行不被覆盖。

## 发送内容与原生会话

预览独立显示当前完整的任务上下文，包括此前提交的脱敏摘要、相关会话历史、范围、验收条件和 Wiki 引用，以及可取得的运行结果、检查点和 Git 快照。未确认的修改不会发送。已有当前上下文时，旧运行中的过期任务资料不会重复进入交接。超过支持的证据范围时返回错误，避免截去用户未确认的内容。交接不发送整段聊天、原始日志或截图。提示词仍要求执行器把 Done 留给用户、不推送主分支、不部署正式环境。既有工具和权限边界继续适用。

Codex 近期文本预览通过官方 App Server 的只读调用读取运行记录对应的原生会话。该预览仅在用户请求时加载，不开启推理，也不进入续作提示词。两个执行器都提供在原项目目录打开原生会话的命令。Claude Code 的完整会话在官方客户端读取。归档、删除及后台列表移除由相应的官方客户端管理。IssueRelay 的保留设置只清理本应用的运行日志。 [Codex App Server](https://learn.chatgpt.com/docs/app-server) · [Claude Code 会话管理](https://code.claude.com/docs/en/sessions)

## 验证

使用临时 SQLite、合成 Linear、假执行器和协议替身验证续作持久性、原生恢复与新会话分支、重新读取预览、状态边界和只读文本提取。原生客户端、Windows 与真实 Linear 的结果单独记录。
