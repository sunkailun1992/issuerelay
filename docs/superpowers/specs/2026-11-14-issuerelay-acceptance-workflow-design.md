# 独立验收、退回与原生会话设计

## 目标

同一工单能追溯需求和方案、开发、自测、可选独立验证、退回修复、复验与归档。方案、开发和验证都由实际 Codex 或 Claude Code 会话执行。一个阶段只执行一次，用户确认后才可启动；验证必须新开原生会话。

## 生命周期

1. 方案与开发继续沿用现有预览和人工确认。方案保留原评论，开发完成后保留交付版本、工作目录和自测证据。
2. 开发达到待验收时，可选择直接人工验收或启动独立验证。独立验证预览展示来源开发运行、执行器、模型、权限、目录、待验证交付标识及范围。验证任务不得修改交付源码、Linear 状态或部署。只在明确授权的隔离环境执行必要的测试写入。
3. 独立验证保留原生会话 ID、开始、检查点、结束、证据及通过、未通过、无法完成三种结论。执行失败、取消、退出码或缺报告不等于验收不通过或通过。通过的结论只适用于绑定的交付版本。
4. 用户确认退回后保留前一轮开发和验证，记录失败项、复现与所验版本。当前 Linear 修订若已处理，提供工单入口更新实际需求，并沿用派发复核。应用不写 Linear 的中间状态。修复进入新的开发轮次，引用原失败证据；只处理剩余差额。
5. 复验绑定修复后的新开发运行和交付版本。确认预览失效、原运行变化、证据为空或另一阶段并发时，应明确报原因。旧失败与新复验都能从同一工单时间线回溯。
6. 已实际开始并终止的每轮显示 Wiki 归档待补、有效或不可读取。保留原页面和提交 SHA，提交推送由执行会话按已配置 Wiki 的规则完成。面板与 MCP 读回回执。等待和排队未启动项不计入归档缺口。未通过的验收不可用于标记完成；用户仍可在未开启独立验证时按现有路径人工验收。

## 原生会话

- 方案、开发和验证以提供方可信启动事件为准。收到 Codex `thread.started` 或 Claude Code `system/init` 的合法 UUID 后立即保存并通知，和尝试的启动时间及执行器匹配。续跑的会话 ID 以实际启动事件为准。
- Codex 的桌面入口用固定的 `codex://threads/<session-id>`。保证项目侧栏可见须由真实桌面宿主创建并回读项目归属、标题和 ID。公开 App Server 支持创建持久线程，但独立 server 到桌面索引的可见性仍需验收。公开深链预填提示词时须由用户提交。 [Codex App Server](https://learn.chatgpt.com/docs/app-server) · [桌面深链](https://learn.chatgpt.com/docs/reference/commands#deep-links)
- Claude Code 支持会话结束后通过 `claude --desktop --resume <session-id>` 打开同一个原生会话。保留运行中的 ID 和开始、过程、结果。启动时自动出现在桌面侧栏需核对目标客户端能力，无法提供时界面须区分可定位与桌面已验证。 [Claude Code Desktop](https://code.claude.com/docs/en/desktop#coming-from-the-cli)
- 若桌面宿主具备创建和读取能力，它承担该阶段唯一执行，IssueRelay 记录宿主、项目和原生会话关系。按提供方分别验收，不借创建第二个会话伪造同一运行可见性。

## 实现与边界

第一步复用 `jobs.session_id`、当前运行的启动时间和引擎事件。面板只复制固定模板构造的链接或命令，不引入通用 URL 打开能力。保留现有只读预览和终态续接。

独立验收与退回需要单独的本机工作流记录。推荐复用现有目录互斥、执行器选择、启动、确认及结果存储，独立验证使用明确的阶段关系和独立验收结论，保留所有开发记录。外部客户端接入以受支持的宿主或交接入口为准。验证轮次不得因修改验收元数据而触发普通 Linear 开发重派。添加新的确认动作时，必须从同一引擎向桌面和 MCP 提供预览、提交时复核、一次性消费及结果读回。

验收预览绑定实际交付指纹、完整获批简报和 Linear 修订。待确认的新简报可随该次验收确认一并保存。启动、结束和标记完成重核版本与获批条件。修复的续作、重试和后续开发持续保留失败验收关联，完成前需要独立复验。

验收执行器从经校验的 Git 提交和清单制作临时副本，原工作目录保持只读。固定沙箱配置允许联网，供授权原型、本机服务和测试依赖使用；预览明确显示联网能力，执行范围由获批任务约束。此配置不提供按域名的隔离保证。Codex 使用 workspace-write，Claude 在支持系统上启用文件沙箱并禁止脱离沙箱；原生 Windows Claude 暂保留文件检查能力，需要命令实跑的场景报告无法完成。

所有执行权限、命令参数、进程终止和 Linear 写入继续遵守仓库规则。公开实现、测试与报告只用合成编号和数据。
